Fern

plant.js draws every specimen on this site the way most computer graphics has drawn a plant since the 1980s: a function that decides a branch's length and angle, draws it, then calls itself for whatever grows from the end — a plain recursive tree, however much detail it wears. A note here already said so plainly. This room draws a fern a different real way: not a shape rule calling itself, but four flat equations and a weighted coin flip, run tens of thousands of times, with no idea what a fern looks like built into any of them.

In 1988 the mathematician Michael Barnsley showed that four affine transformations — each one just a scale, a rotation, and a shift applied to a single point — reproduce a black spleenwort fern's outline almost exactly, if you pick one transformation at random on every step (weighted 1%, 85%, 7%, 7%) and plot wherever it sends the point before. Run that “chaos game” long enough and the plotted points converge on the fern no matter where the very first point started — the shape belongs to the four equations themselves, their attractor, not to any one run through them.

The four equations only ever draw one exact fern. “Lean” isn't part of Barnsley's own model — it's a shear this room adds afterward, nudging every plotted point sideways by an amount proportional to its own height, so the whole frond tips left or right. Every point still lands exactly where the four unbent equations put it; only the on-screen bend is this room's addition. “Grow again” reruns the chaos game from scratch with a fresh random sequence — watch closely and no two runs place their points in the same order, but the attractor gives them nowhere else to end up, so the picture that comes out doesn't change.

Sources: M. F. Barnsley, Fractals Everywhere (Academic Press, 1988), the chapter introducing iterated function systems, with the fern as its standing example. The four transformations and their probabilities used here are the same published coefficients, unchanged since.
